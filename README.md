# Morris Hsieh — Personal Website

Personal site for Morris Chun-Mo Hsieh (谢君模), built on the N5 minimal resume template.

**Live URL:** https://morrishsieh.me

Sections use path URLs (`/about/`, `/dining/michelin/`, `/faith/`) — no `#` in the address bar. GitHub Pages serves a copy of the page at each path so refresh works.

## Sections

- **Home** — Hero with NYC skyline
- **About** — Bio, interests, skills
- **Resume** — Work experience & education (GPA only, no semester grades)
- **NYC** — City life, history, walking routes
- **Travel** — Journey, hotel collection, and a walking guide
- **Dining** — Restaurant picks in NYC & abroad
- **Gallery** — Photo gallery with filters
- **Contact** — Email & social links

## Project structure

The site is authored as one folder per component and assembled into a plain
static site by a small build script — no framework, no runtime dependencies
on GitHub Pages.

```
components/<name>/        one folder per section (home, about, resume, nyc,
                           travel, dining, gallery, contact)
  <name>.html                the section's markup (required)
  <name>.css, <name>.js      section-specific styles/behavior (optional)
  img/                       images this section uses — add new photos here
  data/                      JSON data this section reads (nyc, travel only)
  scripts/                   Python data builders (nyc, travel only)

theme/                     third-party N5 template + UI plugins, unmodified
  css/, js/, fonts/

assets/                    Morris's own shared styles/scripts/images used
  css/, js/, img/          across every section (site chrome, CSS variables)

bootstrap/                 Bootstrap CSS/JS (third-party, unmodified)
vendor/                    Font Awesome + Google Fonts, generated by
                           `npm install` (see scripts/vendor-assets.js) — not
                           committed to git

build/
  template.html            page skeleton with <!--@include:name--> markers
  build.js                 assembles template.html + components/* into dist/

dist/                      generated static site (gitignored) — this is what
                           actually gets deployed; never edit it by hand
```

**Adding a new section:** create `components/<name>/` with a `<name>.html`
partial (and `img/`, `css`, `js`, `data` as needed), add
`<!--@include:<name>-->` to `build/template.html` where it should appear, and
a matching nav link. Run `npm run build` to see it.

**Adding a photo to an existing section:** drop the image into that
section's `img/` folder and reference it from the section's `.html` (or
`.css`) with a path relative to the site root, e.g. `img/<name>/photo.jpg`.

## Local development

```bash
npm install     # also vendors Font Awesome + Google Fonts into vendor/
npm run build   # assembles components/* into dist/
npm start       # builds, then serves dist/ at http://localhost:8000
```

## Deployment

The public site is **https://morrishsieh.me** (Cloudflare). This GitHub
repo is source only — it should stay **private**, and GitHub Pages should
stay **off**. Do not publish `dist/` to `*.github.io`.

`.github/workflows/ci.yml` runs `npm ci` and `npm run build` on pushes

## Travel data (Google Timeline)

Rebuild travel trips and map from a Google export:

```bash
npm run build-travel -- /path/to/takeout.zip
# or drop export folder:
python3 components/travel/scripts/parse-timeline.py /path/to/Takeout/
```

**Important:** Recent Google Takeout "Timeline" exports often contain only settings (history is on-device). For full visit data, export from the **Google Maps app**:

1. Maps → Profile → **Your Timeline**
2. Settings (gear) → **Export Timeline data**
3. Save the file, then run `npm run build-travel` with that path

Home bases are fixed: **Taipei** (until Aug 1, 2022) and **NYC** (since Aug 2, 2022). A trip starts when you leave base and ends when you return — shown as home pins, not travel destinations.

### Add a trip from a phone Timeline export

`build-travel` rebuilds every trip from a full history file. An on-device export (`Timeline.json`, from Maps → Your Timeline → Settings → Export) only covers recent days, so running it on that file would wipe older trips. Merge the new ones instead:

```bash
python3 scripts/import-timeline-trips.py /path/to/Timeline.json          # print new trips
python3 scripts/import-timeline-trips.py /path/to/Timeline.json --write  # merge into data/travel.json
```

Requires `reverse_geocoder` (`pip install reverse_geocoder`), the same offline geocoder as `parse-timeline.py`. Place visits outside the home radius become one trip per time away. Dates are the phone's local calendar days. Cities come from those visits, not from the flight path. Do not commit `Timeline.json` or `location-history.json`.

### Hotel Collection

`/travel/hotels/` is a second Travel tab. `data/hotels.json` is the luxury-hotel catalog (Waldorf Astoria, The Ritz-Carlton, Four Seasons, Fairmont). Each catalog row has `brand` plus `family` (the loyalty group that brand belongs to):

| Brand | Family |
| --- | --- |
| Waldorf Astoria | Hilton Honors |
| The Ritz-Carlton | Marriott Bonvoy |
| Four Seasons | Four Seasons |
| Fairmont | ALL Accor |

`data/hotel-visits.json` is the stay log. Name, brand, family, city, and coordinates come from the catalog via `hotelId` — do not copy those onto the visit. Visited hotels show as fixed-size pins on the map. The map opens centered on the Atlantic (Europe and the Americas together). Stay cards sit in a vertical timeline in the right-hand column.

**Add a visit:** look up the hotel in `hotels.json`, then append a visit. `type` is `stay` (overnight; `date` is check-in, `checkout` is the morning you left, nights are `checkout − date`) or `stop-by` (dropped in for a drink, meal, or a look — no `checkout`).

```json
{
  "id": "kebab-name-MMDDYY",
  "hotelId": "catalog-id",
  "type": "stay",
  "date": "YYYY-MM-DD",
  "checkout": "YYYY-MM-DD",
  "pictures": []
}
```

Photos use the dining convention: `components/travel/img/visits/<id>/`, cover `0.jpeg`, then `1.jpeg`, `2.jpeg`, … plus matching `*.thumb.jpeg` files.

### Guide

`/travel/guide/` is a phone-first walking guide. One JSON file per city lives in `components/travel/data/guide/`, in the order listed by `index.json`. The page copy is English by default, with an EN / 中文 toggle (Simplified Chinese, stored in `localStorage` as `travel-guide-lang`).

City cards use `cover`. It defaults to a flag in `components/travel/img/flags/` (`coverFit: "contain"`). To use a photo later, set `cover` to a path under `img/travel/` and `coverFit` to `"cover"`.

**Bring in a new export** (same shape as itinerary v1; v2, v3, …):

```bash
npm run import-guide -- path/to/itinerary_v2.json
npm run build
```

That rewrites `index.json` and each `<id>.json`. The script drops personal names, flight and train numbers, emails, phone numbers, prices, confirmation codes, and “reserve now” notes. Place and dish names stay in the original language. Simplified Chinese for the prose lives in `scripts/guide-zh.json`, keyed by the sanitized English. A string with no entry is left in English and printed as a warning.

Adding or editing a stop in a city file is enough for the page. A new city also needs its id in `index.json` (the importer does this). `npm run build` then adds `/travel/guide/<id>/` so a refresh stays a 200.


`arrive` and `leave` are a clock (`5:05 PM`, `~9:00 PM`) or, when the label is a phrase, `{ "en", "zh" }` (`after midnight` / `午夜后`, and the same for morning, evening, flexible, TBD). The Chinese page shows a clock in 24-hour time (`17:05`, `约21:00`). `subtitle`, `nativeName`, `hours`, `notes`, `mustSee`, `mustOrder`, `backups`, `alternatives`, and `transit` can be omitted. `transit` on a stop is the leg **to the next stop**; the last stop has none. `transit.segments` is one entry per mode, in order. A v2 segment can also carry `line`, `direction`, `from`, `to`, `stops`, `distanceM`, and `frequency`. The timeline shows `line → direction · duration` (or `Walk · 5 min`). Boarding stop, alighting stop, stop count, and frequency sit behind Details. `ticket` and `alternative` are the same kind of short note. `duration` is `null` when that part has no time — the page shows an em dash, not the word null. `mode` picks the icon: `walk`, `flight`, `train`, `metro`, `tram`, `bus`, `taxi`, `lift`. `gettingAround` is the city’s compact ticket note.

`type` is `sight`, `restaurant`, `hotel`, `airport`, `station`, `church`, `bar`, `daytrip`, or anything else (shown as a generic stop). A `daytrip` row links to that city. Two stops in a row have no transit line between them. A restaurant's `backups` open under Backups / 备选. The flights before Berlin and after Brussels stay off the city pages. Sights, churches, and bars list `mustSee` (Must see / 必看). Restaurants and backups list `mustOrder` (Must eat / 必吃), plus `mustOrderNote` when the export has one. Chinese comes from `must_see_zh`, `must_order_zh`, and `must_order_note_zh` when the export has them. `founded`, `foundedNote`, and `cuisine` show on those meal cards when the export has them. `ticket` is a Tickets / 票务 line. `bookingUrl` is the Book link on that line. `booked: true` is a Booked chip with no confirmation code. The to-book checklist itself stays off the page. Changelog, archive, list, and checklist keys in a newer export are ignored. Re-run the importer to pick up the next file.

`status` is `confirmed` (quiet), `tentative` (light marker), or `needs-decision` (a TBD chip). `alternatives` are the other options when the export has them, without prices.

`draft: true` shows a small Draft / 草稿 tag in the city header. `website`, when it is an `http` or `https` URL, is a globe icon only — the address is not printed. The other icon opens Google Maps directions to `lat,lng`, or to the place name when there is no coordinate.

## Updating content

- **Dining visits:** Tell the agent the restaurant and date. It checks Michelin + award lists (local cache `components/dining/rankings.json`, lookup via `python3 scripts/dining-rankings.py lookup "Name"`), writes `data/michelin.json` and/or `award.json`, creates `img/visits/<id>/`, then after photos: rename, `npm run compress-dining -- <id>`, commit, push. Dual-listed meals use the **same `id`** and one photo folder.
- **Dining photos:** Cover is `0.jpeg`. Other files become `1.jpeg`, `2.jpeg`, … in original-filename A–Z order. Compress **that visit only**. Keep camera originals out of git.
- **Other photos:** Add images to `components/<section>/img/` and reference them from that section’s `.html`.
- **NYC spots:** Update cards in `components/nyc/nyc.html`
